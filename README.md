# Omni for M500

Генератор документации по терминалам РЭ/БУ: бланк уставок в docx и
обновление таблиц (уставки, суммарные сигналы, перечень сокращений)
в latex-проекте руководства по эксплуатации.

## Установка и запуск

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python main.py
```

Запускать нужно из корня проекта: пути к `devices.ini`, `origin.docx`,
`abbr.json`, `dictionary.json` и каталогу сборки `latex_build` берутся
от каталога проекта, а не от текущего рабочего каталога.

Пакет поддержки может содержать `fsu-information.json` — если файла нет,
приложение автоматически работает по `GROUPING.json`/`meta.json`.

Логи пишутся в окно интерфейса и в файл `logs/app.log`.

## Единицы уставок

В главном окне есть два списка:

* **«Единицы уставок»** — `Первичные`, `Вторичные` (по умолчанию) или
  `Относительные (о.е.)`;
* **«Единицы времени»** — `мс` (по умолчанию) или `с`;
* галочка **«Генерировать из fsu-information»** — по умолчанию включена:
  таблицы уставок (бланк и РЭ) собираются по `fsu-information.json`
  (функциональные блоки, значения и шаг **в о.е., как в файле, без
  коэффициентов**). Если снять — работает прежний путь
  `GROUPING.json` + `meta.json` с пересчётом единиц;
* галочка **«Преобразовывать Шаг»** — по умолчанию включена. Если снять,
  столбец «Шаг» берётся из `meta.json` без коэффициента (диапазон и значение
  по умолчанию при этом всё равно пересчитываются). Режим нужен для
  проверки пересчёта.

Точность чисел в столбцах «Значение / Диапазон», «Шаг» и «Значение по
умолчанию» задаётся шагом уставки: при шаге `0,005` выводится
`0,000…300,000`, при шаге `0,01` — `0,00…1,00`.

Выравнивание делается только по «ровному» шагу (не более трёх значащих цифр:
`0,001`, `0,005`, `0,01`, `5`, `0,0125`). Если шаг «кривой» — например,
пересчитанный `0,001 / 1200 = 8,333e-7` или `0,001 / 1,83 = 0,00054645` — к
нему не приводят, и значения выводятся свободно: `0,04…30`, шаг `8,333e-7`.
Кроме того, если шаг крупнее самих значений (шаг 5 сек, умолчание 0,1),
точность увеличивается, чтобы не потерять цифры.

Все три настройки применяются к бланку уставок в docx и к latex-таблицам
уставок, которые собирает кнопка «Обновить таблицы с уставками в РЭ».

Пересчёт выполняется по данным пакета поддержки, без хардкода:

* в `EXTENSION.json` для каждой трансформации перечислены доступные системы
  единиц (`Units` + `Type`), масштаб единицы (`Coefficient`, например `0.001`
  для «кВ» и «сек»), параметр-коэффициент (`CoefficientParameter`, например
  `CtRatio`) и база (`BasisParameter`, `NominalSecondaryValue`);
* значения параметров-коэффициентов берутся из `meta.json`;
* пересчитываются диапазон (min…max), шаг и значение по умолчанию.

Формула: `base = value / P`, далее `base * P * C` для первичных,
`base * C` для вторичных, `base / B` для о.е. (`P` — параметр-коэффициент,
`B` — база, `C` — масштаб единицы).

Подписи единиц в документах приводятся к принятым обозначениям:

| в пакете | в бланке и РЭ |
|---|---|
| `сек` | `с` |
| `Эл. градусы` (и `град.`) | `град.` |
| `А (первич.)`, `кВ (первич.)`, `Ом (первич.)` | `А (перв.)`, `кВ (перв.)`, `Ом (перв.)` |
| `А (вторич.)`, `В (вторич.)`, `Ом (вторич.)` | `А (втор.)`, `В (втор.)`, `Ом (втор.)` |

Проверка на пакете: `3I0ср ООВП` 2400 А (перв.) → 2 А (втор.) → 2 о.е.;
`3U0ср ООВП` 22000 В → 22 кВ (перв.) → 10 В (втор.) → 0.1 о.е.;
`Rср ДЗ-ФФ-1` 549 Ом (перв.) → 300 Ом (втор.) → 3 о.е.
Параметры без трансформации (например, время в мс) выводятся как в `meta.json`.

Уставки времени без трансформации в пакете (например, время АПВ) тоже
пересчитываются при выборе `сек` — по точному определению единиц
(1 сек = 1000 мс), потому что коэффициент `мин` в пакете задан неточно и в
списке выбора не предлагается.
